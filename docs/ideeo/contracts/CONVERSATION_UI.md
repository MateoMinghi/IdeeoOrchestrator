# Authenticated React conversation entry

After an interrupted send, **Reload conversation** checks the pending append key and reads authorized history. This also works for the first message in a newly created conversation. A committed result restores the answer and clears the matching draft. An uncommitted result keeps the draft and explains that the next request needs its own context. A workspace claim displays a warning to check the external result. If the user edits a pending message before checking its status, the first send checks the original key and keeps the edit for an explicit send. Refreshing the browser tab still discards in-memory pending keys.

`ideeo.html` mounts `src/ideeo/IdeeoChat.tsx` in the existing React project. It reuses the existing send button, chat-bubble presentation, theme tokens, fonts and localization. Pure bubble styles are extracted and re-exported so the upstream UI keeps its existing imports. This entry does not load the upstream App/store, desktop setup, analytics or legacy conversation routes. It is the first bounded product consumer, not a completed adaptation of the entire upstream desktop application.

`createProductClient` accepts a tenant-owned asynchronous token callback. The standalone entry uses the actual PayMe `POST /api/nico/token` cookie exchange. Hosting must route that same-origin path to the intended tenant API and `/v2` to the product API. There is no configurable browser-selected tenant/provider URL and no token paste/login form. The product never accepts the cookie itself as proof. Tokens remain in operation-local memory and travel only in the product Authorization header; product requests omit cookies and reject redirects. Each operation first checks `/v2/session`, then uses the separately authorized conversation endpoints. HTTP responses are bounded and uncached. Client validation supplements, and never replaces, server authorization.

The UI sends protocol-3 free-form messages with the disclosure marker and a visible explanation that sending shares the message with AI. The evaluation entry asks for invented examples without personal, banking or authentication details. All answers and messages render as inert escaped text; Markdown images, HTML, scripts and external links are not activated. Only committed history appears as completed content. The synchronous composer has loading, empty, unavailable, denied, expired, budget and conflict states. Enter sends, Shift+Enter adds a line and IME composition does not send. Append operations allow seventy seconds for the bounded workspace workflow; other client operations retain thirty seconds, and user cancellation still aborts immediately.

The conversation UUID is retained in the URL fragment only, as a reload locator, never authority. Tokens, drafts and transcripts are not saved to browser storage. Reload obtains fresh tenant proof and pages the current authorized history, at most 1,000 turns. A pending send retains its creation and turn idempotency keys in memory; retrying unchanged text in that mount uses the same keys. A lost successful response is therefore reconciled by replay/history without another model dispatch. Reload discards a pending draft and key; it does not automatically resend uncertain work. Durable pending-turn recovery and cross-device drafts remain unimplemented.

Starting another conversation, changing the token source, hiding the document or revalidating access aborts the old request and fences its late response. Displayed history is cleared before revalidation and on hidden-document transitions. Focus and a 30-second visible-page check refresh current authority. Revocation cannot erase content already seen or copied; this is a bounded refresh behavior, not push revocation. A different caller cannot load the UUID under its new proof. The server's complete caller binding, current grant/channel checks and encrypted store remain authoritative.

The fixture combines a disposable browser profile, actual PayMe cookie exchange/API, actual product process, fresh PostgreSQL and a scripted model. Its local proxy adapts the fixture browser origin to the API's configured synthetic origin; that is not evidence of a deployed tenant's reverse proxy, cookie/CORS configuration or native SDK adoption. Cross-tenant UI denial switches the fixture's token source to an independently signed second tenant. No real cookie, account or customer record is used.

`pnpm build:ideeo-ui` writes a standalone local artifact to `dist/ideeo`. It does not host, deploy or configure tenant routes. The separately activated live browser campaign now exercises this same React entry against Luna with synthetic identities/content and the existing twelve-call cap. It checks committed answers, revised writing, reload, lost-response replay, the color tool, revocation and tenant switching. Scripted-only inert HTML injection remains separately tested. The current fixture builds `ideeo.html` before starting the tenant resources and previews that exact bundle. The product stylesheet imports the shared theme and scopes Tailwind class discovery to the Ideeo entry and its shared chat components. Include any new shared component that supplies utility classes in `src/ideeo/styles.css`. Historical development-server stalls and interrupted-worker failures are recorded in the verification evidence. Independent review, different-human acceptance, browser reliability qualification, broader live semantics, tenant hosting/SDK/WhatsApp device adoption, production operation and the remaining upstream application adaptation are outstanding.
